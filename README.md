3.项目框架
3.1.框架
本项目框架是基于Vue2.0的框架设计，第三方依赖库通过npm进行管理，ESlint进行代码编写规范控制，使用webpack完成项目的构建和打包。
使用Axios获取服务端数据，再由响应式处理渲染到页面，完成页面的加载。


3.2.项目目录结构


3.2.1 public
存放项目的入口文件（index.html）和网站的缩略logo标志。

3.2.2 src
项目中的主要代码都在该目录下。

3.2.2.1 api
项目所有网络相关的接口统一在此目录下进行管理。根据不同的功能或类型的接口，创建单独的.js文件，便于进行接口API维护。
3.2.2.2 assets
存放项目的静态资源文件，如图片、字体包等资源
3.2.2.3 components
项目中封装的组件统一存放在该目录下，便于查找项目知识库中已封装组件
3.2.2.4 fillters
存放项目中常用的过滤器函数，按过滤器种类分类，或统一写在该目录下的index.js中
3.2.2.5 i18n
存放项目国际化配置文件及本地语言包的存放目录
3.2.2.6 router
存放各功能页面对应的路由地址，及相关配置文件。以功能模块分类，创建不同的子模块路由，便于进行路由管理。
3.2.2.7 store
存放数据持久化的逻辑代码文件 ，按照数据类别分类，创建不同的数据持久化文件。
3.2.2.8 styles
存放公共的样式文件
3.2.2.9 views
存放功能页面代码的目录，包含大部分的功能页面内代码。

3.2.3 babel.config.js
Babel的配置文件，用于进行项目构建时的语法转化。
3.2.4 package-lock.json 和packkage.json
该文件是项目中使用的组件及插件版本管理文件，为了保持协作开发时组件版本的一致性。

5 技术要点
5.1 项目release代码的杂凑处理
1.使用webpack进行前端资源的加载和打包。构建和打包时会根据模块间的依赖关系进行静态分析，将这些模块按照指定的规则生成对应的静态资源，并讲多种静态资源js、css、sass等转化为一个静态文件，减少页面请求。
2.同时会对代码进行压缩和混淆，增强系统的安全性。
